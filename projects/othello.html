Summary

Othello AI. A game-playing agent written in C and parallelised with MPI. A master process hands candidate moves to worker processes, each worker searches its moves with minimax and alpha-beta pruning, and the master picks the best result. The agent played in a tournament framework against other players.

Process scheduler. A simulator that runs processes from input files under first-come-first-served, round-robin with a configurable time quantum, and priority scheduling, and handles processes requesting and releasing shared resources.

My role

An individual project, so everything here is mine: the parallel search, the evaluation function, and the scheduler simulator. The only thing I did not build was the tournament framework the agent played in.

What I built

Othello AI

  • A master process that hands candidate moves to worker processes via MPI. Each worker searches its moves with minimax and alpha-beta pruning, and the master picks the best result.
  • An evaluation function that combines piece difference, mobility, edge stability, and corner control.
  • Re-weighting of those terms by game stage:
    • Opening: mobility and corners.
    • Middle game: stability.
    • Endgame: piece count and corners.
  • The agent played in a tournament framework against other players.

Process scheduler

  • A simulator that runs processes from input files under first-come-first-served, round-robin (configurable time quantum), and priority scheduling.
  • Handling of processes requesting and releasing shared resources.

Interesting problems

Splitting one search across processes

A minimax search is one big tree, and MPI processes do not share memory. The master hands each worker its own candidate moves, each worker searches them independently with alpha-beta pruning, and the master compares the results and plays the best one.

An evaluation that changes its mind by game stage

What makes a good Othello position depends on how far into the game you are. The evaluation function combines piece difference, mobility, edge stability and corner control, but weights them differently: mobility and corners in the opening, stability in the middle game, piece count and corners in the endgame.

Scheduling processes that share resources

The scheduler reads processes from input files and runs them under first-come-first-served, round-robin with a configurable time quantum, or priority scheduling. Processes also request and release shared resources along the way, so the simulator has to handle a process that wants something another process is still holding.
